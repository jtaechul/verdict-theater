# 판결극장 (Verdict Theater)

> 실제 법원 판결을 재구성한 가족 드라마. 유튜브 롱폼 12분 + 쇼츠 3편 자동 제작 파이프라인.
>
> 모든 결정사항은 [`CLAUDE.md`](CLAUDE.md) 에 있다. 착수 절차는 [`STARTGUIDE.md`](STARTGUIDE.md).

## 폴더가 무슨 뜻인지 (한 줄씩)

| 폴더 | 무엇이 들어가나 | 지금 상태 |
|---|---|---|
| `prompts/` | **★ 이 사업의 핵심 자산.** 대본을 어떻게 쓸지 알려주는 지시문 4개 | **작성 완료** |
| `src/` | 파이프라인 코드 (판례 수집·대본 생성·영상 제작을 실제로 실행하는 부분) | 검증기 1개 |
| `state/` | 어느 회차가 어디까지 진행됐는지 기억하는 파일들. **파이프라인의 두뇌** | 빈 파일 4개 생성됨 |
| `data/cases/` | 법제처에서 받아온 판례 원문 (판례번호별 파일) | **실제 판례 3건** |
| `data/scripts/` | 완성된 대본 (회차별 파일) | **검증 샘플 1편** |
| `assets/char/` | 등장인물 컷아웃 이미지. 배경이 뚫린 PNG. 인물 7명 × 17포즈 = 119장 | 폴더만 생성됨 |
| `assets/bg/` | 배경 사진 30장 (JPG). 블러 처리해서 맨 아래 깔린다 | 비어 있음 |
| `assets/prop/` | 소품 이미지 (서류, 손 등) | 비어 있음 |
| `assets/bgm/` | 배경 음악 8트랙 | 비어 있음 |
| `assets/amb/` | 앰비언스 5종. 장소별 공기 소리. **무음 구간을 없애는 용도** | 비어 있음 |
| `assets/sfx/` | 효과음 10종 (의사봉, 발소리, 심장박동 등) | 비어 있음 |
| `assets/sheets/` | 캐릭터 시트 원본 (18칸짜리 큰 그림). 잘라내기 전 보관용 | 비어 있음 |

`.gitkeep` 이라는 빈 파일이 각 폴더에 하나씩 들어 있다.
GitHub은 **빈 폴더를 저장하지 못하기 때문에**, 폴더를 유지하려고 넣어둔 표식일 뿐이다.
그 폴더에 진짜 파일이 들어오면 지워도 된다.

## 인물 코드 (assets/char/ 하위 폴더 이름)

고정 배우 7명을 회차마다 다른 역으로 돌려 쓴다. **극단 개념이며 의도된 설계다.**

| 코드 | 역할 | 외형 | 상태 |
|---|---|---|---|
| `F50A` | 억울한 주인공형 | 짧은 파마, 지친 눈, 남색 니트 | 시트 생성 완료 |
| `F50B` | 악역 올케·동서형 | 단정한 단발, 날카로운 눈매 | 미생성 |
| `M50A` | 악역 장남형 | 짧은 머리 희끗, 회색 정장 | 미생성 |
| `M50B` | 차남·사위형 | 벗은 이마, 점퍼 | 미생성 |
| `F70` | 노모 | 흰 머리 파마, 굽은 어깨 | 미생성 |
| `M70` | 노부·망인 | 흰 머리, 마른 체구 | 미생성 |
| `JUDGE` | 판사 | 검은 법복 | 미생성 |

파일 이름 규칙: `assets/char/{인물코드}/{구도}_{표정}.png` — 예) `assets/char/F50A/bust_sad.png`

## 자동 실행 파일(워크플로)

GitHub이 **자동 실행 파일은 반드시 저장소 맨 위 `.github/workflows/` 에만** 두게 강제한다.
다른 위치에 넣으면 GitHub이 아예 읽지 않는다. GitHub 규칙이라 우회 방법이 없다.

| 파일 | 하는 일 | 실행 방식 |
|---|---|---|
| `.github/workflows/build-assets.yml` | 캐릭터·배경 이미지 생성과 가공 | 수동 (버튼) |
| `.github/workflows/collect.yml` | 판례 수집 + 3단 선정 심사 | 주 1회 자동 |
| `.github/workflows/script.yml` | 대본 생성 + 평가 + 개선 (최대 3회) | 수동 / 자동 |
| `.github/workflows/produce.yml` | 영상 제작 + 유튜브 업로드 | 수동 / 자동 |
| `.github/workflows/stats.yml` | 성과 수집 | 주 1회 자동 |

**아직 하나도 만들지 않았다.** 2순위 이후 작업이다.

> ⚠️ 비공개 저장소의 `schedule`(정해진 시각에 자동 반복) 워크플로는, 저장소에 60일간 아무
> 활동이 없으면 GitHub이 자동으로 꺼버린다. 주 1회 수집 커밋이 발생하므로 실제로는 문제없다.

## 절대 하면 안 되는 것

| 금지 | 이유 |
|---|---|
| **완성 영상(MP4)을 커밋** | 편당 200~500MB. 지워도 이력에 영구히 남아 저장소가 되돌릴 수 없이 커진다. `.gitignore` 로 막아뒀다 |
| **API 키를 파일로 저장** | 즉시 유출된다. 반드시 GitHub Secrets에만 넣는다 |
| **댓글에서 개별 법률 상담에 답변** | 변호사법 제109조 제1호 위반 소지. 고정 댓글로 "법률 상담 미제공"을 명시한다 |
| **판사 실명 노출** | 판결문에 실명이 그대로 나온다. 대본에서 완전 삭제하고 "재판장"으로만 쓴다 |
| **가사사건(이혼·재산분할·양육권) 소재 사용** | 가정법원 판결문은 공개되지 않는다. 민사 사건만 쓴다 |

## 지금까지 된 것 / 안 된 것

**완료 (1순위)**
- 폴더 구조 생성
- `state/` 상태 파일 4개 생성 (전부 빈 상태 — 정상)
- `.gitignore` 로 영상·비밀키 커밋 차단
- **프롬프트 4개 작성** — `drama_gate` `script_gen` `script_eval` `shorts_gen`
- `assets/manifest.json` — 대본의 에셋 코드와 실제 파일을 잇는 연결표 (172개)
- **법제처 API 실측** — 실제 판례 수집·정규화 확인. 하급심 필드 공백 문제 발견·대응
- **교차 검증 1건** — 실제 판례로 12분 대본 생성 → 기계 검증 29항목 통과 → 채점 87점
- `src/validate_script.py` — 대본이 규칙을 어겼는지 기계가 검사 (렌더 낭비 방지)

**다음 차례**
1. **GitHub Secrets 등록** ← 손님이 하실 일. 아래 표 참조
2. **반전이 약한 판례로 2편째 교차 검증** ← **여기서 사업 성립이 갈린다**
3. `.github/workflows/` 자동 실행 파일 작성

### 손님이 하실 일 — Secrets 등록

저장소 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**

| 이름 | 값 |
|---|---|
| `LAW_OC` | `panryetheater` |
| `GEMINI_API_KEY` | AI 스튜디오에서 받은 키 |
| `YOUTUBE_CLIENT_ID` | 구글 클라우드에서 받은 값 |
| `YOUTUBE_CLIENT_SECRET` | 〃 |
| `YOUTUBE_REFRESH_TOKEN` | 〃 |
| `NOTIFY_WEBHOOK` | 실패 알림용 (선택) |

- 유튜브 관련 3개는 **5순위 작업이라 지금 없어도 된다.** 막히면 미루셔도 된다
- 한 번 저장하면 다시 볼 수 없다. **메모에 원본을 남겨두십시오**
