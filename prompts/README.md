# prompts/ — ★ 이 사업의 유일한 핵심 자산

판례는 누구나 열 수 있다. 법제처가 무료로 다 공개해 놨다.
**진입장벽은 데이터가 아니라 이 폴더다.**

12분 대본의 약 82%는 창작이다. 그 창작을 어떻게 시킬지 적어놓은 것이 이 파일들이다.
**이 저장소를 비공개로 두는 이유가 여기 있다.**

---

## 파일 4개

| 파일 | 언제 쓰나 | 입력 | 출력 |
|---|---|---|---|
| [`drama_gate.md`](drama_gate.md) | 판례 수집 직후 | 판례 원문 | 드라마성 100점 채점 → **60점 미만 폐기** |
| [`script_gen.md`](script_gen.md) | 소재 선정 후 | 판례 원문 | 12분 대본 + 컷별 에셋 + 쇼츠 구간 |
| [`script_eval.md`](script_eval.md) | 대본 생성 직후 | 대본 | 100점 채점 + 수정 지시 → **80점 목표** |
| [`shorts_gen.md`](shorts_gen.md) | 대본 통과 후 | 대본 | 쇼츠 3편 세로 대본 → **85점 목표** |

---

## 흐름

```
판례 수집
  → drama_gate.md      60점 미만이면 여기서 버린다 (유일한 폐기 지점)
  → script_gen.md      12분 대본 생성
  → script_eval.md     [별도 호출] 80점 넘을 때까지 최대 3회 보강
  → shorts_gen.md      쇼츠 3편
  → 렌더링 → 유튜브
```

### 왜 판정이 두 군데인가

| | **게이트** (`drama_gate`) | **개선 루프** (`script_eval`) |
|---|---|---|
| 목적 | 제작 여부 결정 | 재미 강화 |
| 대상 | 판례 원문 | 완성된 대본 |
| **폐기** | **있음** | **없음** |
| 위치 | 수집 직후 | 대본 생성 직후 |

걸러낼 지점은 **가장 싼 단계**여야 한다. 대본을 다 만든 뒤 버리면 호출비가 낭비된다.
또 게이트를 선정 단계에 두면 **"소재가 나빴는가 / 대본 생성기가 나빴는가"** 가 분리되어,
성과가 안 나올 때 어느 쪽을 고칠지 알 수 있다.

## 파일 구조 — 모든 프롬프트가 같은 모양이다

```
## 이 파일 사용법 (운영자·파이프라인용 — 모델에게 보내지 않는 부분)
   ...설명, 운영 규칙, 버전 기록...

<!-- PROMPT:BEGIN -->
   ...실제로 모델에게 보내는 본문...
<!-- PROMPT:END -->
```

**워크플로는 `PROMPT:BEGIN` 과 `PROMPT:END` 사이만 잘라서 모델에게 보낸다.**
바깥쪽은 사람이 읽는 메모다.

본문 안의 `{{CASE_JSON}}` `{{SCRIPT_JSON}}` 자리에 실제 데이터를 끼워 넣는다.

---

## 고칠 때 지키는 것

1. **버전 기록을 남긴다.** 각 파일 위쪽 표에 날짜와 변경 내용을 한 줄 추가한다
2. **에셋 코드는 4개 파일에서 똑같아야 한다.** 하나만 고치면 렌더링이 깨진다
   → 기준은 [`../assets/manifest.json`](../assets/manifest.json)
3. **평가는 반드시 별도 호출로 한다.** 대본을 만든 그 호출에서 평가하면 자기 작품을 감싼다
4. **성과가 안 나오면 프롬프트부터 고친다.** 소재나 채널을 바꾸는 건 마지막 수단이다

| **이 프롬프트로 뽑은 대본** | **아직 한 번도 안 돌려봤다** |
| **2편째 재현성** | **미검증. 이 사업의 최대 리스크** |

파일럿 1화는 원본 판례에 "재혼 11개월 전 계약"이라는 강한 반전이 **이미 있었다.**
운이 좋았다.

**반전이 없는 평범한 판례에서 대본이 무너지면, 이건 파이프라인이 아니라 수공업이다.**
`script_gen.md` 의 "D. 반전 만들기 — 판례에 반전이 없을 때" 항목이 그 대비책이다.
**다른 판례 2건으로 교차 검증하기 전에는 다음 단계로 넘어가지 않는다.**
