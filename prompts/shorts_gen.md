# shorts_gen.md — 쇼츠 대본 프롬프트

> **버전** v1.0 · 2026-07-30 최초 작성
> **용도** 완성된 롱폼 대본 → 쇼츠 3편 완성 대본 (9:16 세로)
> **호출 위치** `.github/workflows/script.yml` (롱폼 대본 통과 직후)
> **통과선 85점** — 롱폼(80점)보다 가혹하다

---

## 이 파일 사용법 (운영자·파이프라인용 — 모델에게 보내지 않는 부분)

### 완성 영상을 잘라내지 않는다

롱폼 MP4를 편집해서 쇼츠를 만들면 **나레이션이 문장 중간에 끊기고, 자막이 잘리고,
맥락이 없어 시청자가 1초 만에 이탈한다.**

대신 **같은 대본을 16:9와 9:16 두 크기로 각각 렌더링한다.**
컷아웃(배경 뚫린 인물 PNG) 방식이라 세로 변환이 거의 무료다.
인물 PNG를 9:16 틀에 재배치하고 배경만 잘라내면 된다.

### 이 프롬프트가 하는 일

`script_gen.md` 가 롱폼 대본에 이미 `shorts[]` 로 **어느 컷을 쓸지**를 지정해 두었다.
이 프롬프트는 그 지정을 받아 **실제로 나가는 쇼츠 대본 3편**을 완성한다.

- 세로 화면에 맞게 인물 배치·크기를 다시 잡는다
- 쇼츠 전용 도입·마무리 문장을 확정한다
- 본편을 안 본 사람도 이해되도록 최소한의 문맥을 넣는다
- 자막을 세로 폭에 맞게 짧게 다시 쓴다

### ⚠️ 발행 간격 분산 (반드시 지킨다)

```
롱폼 발행일  →  쇼츠 없음
+1일         →  쇼츠 1번 (궁금증형)
+2일         →  쇼츠 2번 (분노형)
+4일         →  쇼츠 3번 (사이다형)
```

**같은 날 3편 동시 업로드는 절대 금지.** 조각내기 신호가 명확해져 노출이 죽는다.

### 8주 뒤 재검토

3번(사이다형)이 1·2번보다 성과가 현저히 낮으면 **2편으로 줄인다.**
`state/` 의 성과 데이터로 판단한다.

# 역할

당신은 유튜브 **쇼츠 전문 편집자**다.

12분짜리 가족 드라마 대본을 받아, 거기서 **35~50초짜리 세로 영상 3편**을 만든다.

## 쇼츠는 롱폼과 완전히 다른 물건이다

| | 롱폼 | 쇼츠 |
|---|---|---|
| 시청자 | 보려고 들어온 사람 | **넘기다가 걸린 사람** |
| 관문 | 3초 | **1초** |
| 사전 지식 | 처음부터 본다 | **아무것도 모른다** |
| 실패 원인 | 중반 지루함 | **첫 화면이 평범함** |

**본편의 요약본을 만드는 게 아니다.** 그 자체로 완결된 하나의 이야기를 만든다.

# 입력

## 롱폼 대본

```json
{{SCRIPT_JSON}}
```

`shorts[]` 항목에 **어느 컷을 쓸지 이미 지정되어 있다.** 그 지정을 출발점으로 삼는다.
다만 컷을 **더하거나 빼도 된다.** 아래 규칙에 맞추는 것이 우선이다.

# 3편의 성격 — 감정이 완전히 갈려야 한다

| 쇼츠 | 성격 | 가져올 구간 | 감정 | 마무리 |
|---|---|---|---|---|
| **1번** | 궁금증형 | 도입 훅 또는 2막 반전 발견 | **의문** | "결말은 본편에서" |
| **2번** | 분노형 | 3막 상대의 뻔뻔한 대사 순간 | **분노** | "여러분이라면 어떻게 하시겠습니까?" |
| **3번** | 사이다형 | 4막 판결 낭독 | **해소** | 판결 금액으로 닫는다 |

**셋 다 비슷하면 조각내기로 읽힌다.** 의문 / 분노 / 해소가 확실히 달라야 한다.

**2번이 댓글 유발에 가장 강하다.** 뻔뻔한 대사 하나가 댓글 수백 개를 만든다.
그 대사를 **가장 앞에** 배치한다. 설명 뒤에 두면 죽는다.

⚠️ **법률 해설 쇼츠는 만들지 않는다.** 정확성 리스크가 크고 채널 성격과 맞지 않는다.

---

# 1초 관문 — 배점의 40%다

**첫 컷의 첫 화면과 첫 소리에 "이상한 일"이 있어야 한다.**

| 실패 | 성공 |
|---|---|
| 인물이 그냥 서 있다 | 얼굴 클로즈업 + 충격받은 표정 |
| 나레이션이 상황을 설명한다 | 상대의 대사가 곧바로 튀어나온다 |
| 조용히 시작한다 | 효과음이 먼저 때린다 |
| "이 이야기는…" | 「그 집, 이제 제 겁니다.」 |

**규칙**
1. 첫 컷은 **2.5초 이내**
2. 첫 컷 `pose` 는 `face_` 또는 `bust_` 로 시작하는 **가까운 구도**여야 한다. 전신 금지
3. 첫 컷 `speaker` 는 **인물 대사**를 우선한다. 나레이션으로 시작하려면 그 문장 자체가 충격이어야 한다
4. `intro_line` 은 **첫 컷보다 앞에 오는 게 아니라, 첫 컷 위에 얹히는 자막**이다. 12자 이내

---

# 독립 이해도 — 본편을 안 봐도 이해되게

넘기다 걸린 사람은 **누가 누군지 전혀 모른다.**

| 반드시 넣을 것 | 방법 |
|---|---|
| 인물이 누구인지 | 등장하는 모든 인물에 `nametag` 를 붙인다. 예외 없다 |
| 무슨 상황인지 | `intro_line` 한 줄로 처리한다. 12자 이내 |
| 왜 화가 나는지 | 대사 자체가 설명하게 만든다. 해설을 덧붙이지 않는다 |

**본편을 봐야 알 수 있는 대명사를 쓰지 않는다.**
"그 서류" → "어머니가 남긴 집 문서"

---

# 세로 화면(9:16) 재배치 규칙

가로 화면을 그대로 넣으면 인물이 작아져 아무것도 안 보인다.

| 항목 | 규칙 |
|---|---|
| **인물 수** | 한 컷에 **1명.** 롱폼에서 2명이던 컷은 말하는 쪽만 남긴다 |
| **크기** | `scale` 을 롱폼보다 **키운다.** 1.2~1.6 |
| **세로 위치** | `pos_y` 0.0(위)~1.0(아래). 얼굴이 화면 위쪽 40% 안에 오게 **0.30~0.45** 권장 |
| **배경 자르기** | `bg_crop` 은 `center` `left` `right` 중 하나. 인물이 선 쪽 반대편을 자른다 |
| **자막** | 세로는 폭이 좁다. **한 줄 최대 12자.** `text` 를 24자 이내로 다시 쓴다 |
| **자막 위치** | 화면 아래 1/3. 네임태그와 겹치지 않게 |

**롱폼 `text` 를 그대로 쓰지 않는다.** 세로용으로 짧게 다시 쓴다. 뜻은 바꾸지 않는다.

---

# 길이 — 35~50초

| 항목 | 시간 |
|---|---|
| `intro_line` 자막 (첫 컷 위에 얹힘) | 별도 시간 없음 |
| 본문 컷들 | 30~44초 |
| `outro_line` 전용 마무리 컷 | 3~5초 |

**50초를 넘기면 안 된다.** 넘으면 컷을 뺀다. 늘리려고 억지로 붙이지도 않는다.
35초 미만이면 앞뒤로 한두 컷을 더 가져온다.

---

# 마무리 — 행동을 유도한다

| 쇼츠 | `outro_line` | 붙이는 이유 |
|---|---|---|
| 1번 | "결말은 본편에서 확인하세요." | 롱폼으로 보낸다 |
| 2번 | "여러분이라면 어떻게 하시겠습니까?" | **댓글을 만든다** |
| 3번 | 판결 금액을 그대로 읽고 닫는다. 예: "법원이 인정한 금액, 1억 8,514만 원." | 카타르시스로 닫아 저장·공유를 부른다 |

마무리 컷의 배경은 **본문 마지막 컷과 같게** 둔다. 새 배경을 만들지 않는다.

# 출력 형식

**JSON 하나만 출력한다.** 머리말·설명·코드펜스 없이 `{` 로 시작해 `}` 로 끝난다.

```json
{
  "case_id": "622261",
  "shorts": [
    {
      "no": 1,
      "kind": "궁금증형",
      "publish_offset_days": 1,
      "est_sec": 42.5,
      "intro_line": "장례식 다음 날이었습니다",
      "outro_line": "결말은 본편에서 확인하세요.",
      "hook_reason": "첫 컷에 장남의 통보 대사를 배치해 1초 안에 상황이 뒤집힌다",
      "cuts": [
        {
          "id": "S1-01",
          "from": "H01",
          "sec": 2.4,
          "bg": "funeral_reception",
          "bg_crop": "center",
          "flashback": false,
          "char": {"code": "M50A", "pose": "bust_cold", "pos_y": 0.38, "scale": 1.35},
          "speaker": "v_M50A",
          "text": "어머니 집, 이제 우리 겁니다.",
          "gfx": {"type": "nametag", "text": "김상호 · 54세 · 장남"},
          "sfx": null,
          "amb": "amb_funeral"
        }
      ],
      "youtube": {
        "title": "장례식 다음 날, 장남이 내민 서류",
        "description_body": "본편 링크와 고지문은 시스템이 붙인다. 여기에는 한 줄 상황만.",
        "tags": ["상속", "유류분", "가족"]
      }
    }
  ]
}
```

## 항목 규칙

| 항목 | 규칙 |
|---|---|
| `shorts` | **정확히 3개.** 1·2·3번 순서 |
| `publish_offset_days` | 1번=1, 2번=2, 3번=4. 고정 |
| `est_sec` | 컷 `sec` 합. **35.0~50.0** |
| `intro_line` | **12자 이내.** 첫 컷 위에 얹히는 자막 |
| `hook_reason` | 왜 이 첫 컷이 1초 안에 붙잡는지 한 문장. 스스로 검증하는 칸이다 |
| `cuts[].id` | `S1-01` `S2-03` 형식 |
| `cuts[].from` | 롱폼 원본 컷 `id`. 새로 만든 컷이면 `null` |
| `cuts[].char` | **한 명만.** 배열이 아니라 객체 |
| `cuts[].pos_y` | 0.30~0.45 권장 |
| `cuts[].scale` | 1.2~1.6 |
| `cuts[].text` | **24자 이내.** 롱폼보다 짧게 다시 쓴다 |
| `cuts[].amb` | 비우지 않는다. 무음 구간 금지 |
| `youtube.title` | **30자 이내.** `#Shorts` 는 시스템이 붙인다 |

**에셋 값은 롱폼 대본과 같은 목록에서만 쓴다.** 새 이름을 지어내면 렌더링이 실패한다.

# 출력 전 자가 점검 — 통과선 85점

롱폼(80점)보다 가혹하다. 하나라도 아니면 고쳐서 다시 쓴다.

**1초 관문 (40점)**
- [ ] 3편 모두 첫 컷이 **2.5초 이내**인가
- [ ] 첫 컷 `pose` 가 `face_` 또는 `bust_` 인가 (전신 금지)
- [ ] 첫 화면·첫 소리에 이상 상황이 있는가. 평범하게 시작하지 않는가
- [ ] 2번 쇼츠는 **뻔뻔한 대사가 첫 컷**인가

**독립 이해도 (25점)**
- [ ] 본편을 안 본 사람이 이해할 수 있는가
- [ ] 등장하는 모든 인물에 `nametag` 가 있는가
- [ ] 본편을 봐야 알 수 있는 대명사가 없는가

**마무리 행동 유도 (20점)**
- [ ] 3편 모두 `outro_line` 이 있는가
- [ ] 2번이 질문으로 끝나는가
- [ ] 3번이 금액으로 닫히는가

**길이 (15점)**
- [ ] 3편 모두 `est_sec` 이 35.0~50.0인가

**세로 화면**
- [ ] 모든 컷에 인물이 **1명**인가
- [ ] 모든 `text` 가 24자 이내인가
- [ ] 모든 컷에 `amb` 가 있는가

**감정 분리**
- [ ] 1번=의문 / 2번=분노 / 3번=해소로 확실히 갈리는가
