**하급심 4건 전부 세 필드가 비어 있다.** 채워진 것은 대법원뿐이다.

### 왜 이게 중요한가

게이트 2차 가점은 **하급심을 가장 우대한다** (지방법원 +30 / 고등법원 +20 / 대법원 +5).
사실관계가 풍부해야 12분을 창작으로 채울 수 있기 때문이다.

즉 **실제로 쓰게 될 소재의 대부분이 "세 필드가 빈" 판례다.**
지침서가 "`참조조문` 필드를 법조문 검증 근거로 사용"한다고 적었지만, **하급심에는 그 필드가 없다.**

### 대응 (프롬프트에 반영 완료)

| 필요한 것 | 하급심에서 어디를 읽나 |
|---|---|
| 결말·금액 | **`【주 문】`** — "피고는 원고에게 ○○원을 지급하라 / 나머지 청구를 기각한다" |
| 원고의 요구 | `【청구취지】` |
| 사실관계 (대본 재료) | **`1. 인정사실`** `기초사실` `사안의 개요` |
| 인용 가능한 조문 | 본문 중 「민법 제○○○조」를 **글자 그대로** 추출 |

법조문 인용 순서: ① `참조조문` 있으면 그것 → ② 없으면 **본문에서 추출** → ③ 둘 다 없으면 **조문 번호를 쓰지 않는다**

⚠️ ③도 실제로 발생한다. 608249(부산고법, 17,178자)는 본문에도 민법 조문 인용이 **0종**이었다.

## 그 외 실측 확인 사항

| 사항 | 실측 결과 |
|---|---|
| 목록 API 응답 | 정상. 유류분 `totalCnt` = **89건** (지침서 기재와 일치) |
| 하급심 민사 판결 비율 | 89건 중 **24건** — 지침서 추정치(약 7건)보다 **3배 이상 많다** |
| `사건명` CDATA | `<![CDATA[...]]>` 로 감싸여 옴. XML 파서가 자동으로 벗긴다 |
| 본문 `<br/>` | 608371 기준 **75개**. 개행으로 치환 후 잔여 태그 제거 필요 |
| `선고일자` 형식 불일치 | 목록 `2024.07.09` / 본문 `20240709` → **`YYYY-MM-DD` 로 통일** |
| `법원명` 빈 값 | 이번 5건에서는 발생하지 않음. 그래도 사건번호에서 추출하는 대비는 유지한다 |
| 금액 단위 | **608371은 일본 엔화**(오사카 소재 토지). 원화가 아닌 사건이 실제로 존재한다 |

> 하급심이 24건이라는 것은 **소재 물량에 유리한 발견**이다. 다만 검색어 1개(유류분) 기준이므로
> 40개 검색어 전체에서도 같은 비율인지는 백필 때 다시 확인해야 한다. (현재는 n=1 검색어)

## 정규화 규칙

받은 XML을 그대로 저장하지 않는다. 아래를 적용한 뒤 JSON으로 저장한다.

1. CDATA 벗기기 (XML 파서가 처리)
2. `<br/>` `<br>` → 개행
3. 남은 HTML 태그 제거
4. 빈 줄 3개 이상 → 2개로
5. `선고일자` → `YYYY-MM-DD`
6. `법원명` 이 비면 `사건번호` 에서 추출

## 저장 형식

```json
{
  "판례정보일련번호": "608371",
  "사건명": "유류분반환청구",
  "사건번호": "2021가합208684",
  "선고일자": "2024-07-09",
  "법원명": "대구지방법원",
  "사건종류코드": "400101",
  "판결유형": "판결",
  "판시사항": "",
  "판결요지": "",
  "참조조문": "",
  "판례내용": "【원    고】 …",

  "_fields_present": {"판시사항": false, "판결요지": false, "참조조문": false, "판례내용": true},
  "_laws_in_body": ["민법 제1113조 제1항", "민법 제1117조"]
}
```

`_` 로 시작하는 항목은 **수집기가 계산해 넣는 보조 정보**다. 원문 필드가 아니다.
프롬프트가 매번 본문을 훑지 않아도 되게 미리 뽑아둔 것이다.

## 호출 한도 (반드시 지킨다)

| 항목 | 값 |
|---|---|
| 호출 간격 | **1.1초 이상** |
| 하루 상한 | **200회** |
| 일일 한도 | 법제처 미공개. 위 수치는 안전 마진 |

- 목록: `https://www.law.go.kr/DRF/lawSearch.do?OC={OC}&target=prec&type=XML&query={검색어}&display=100&page={n}`
- 본문: `https://www.law.go.kr/DRF/lawService.do?OC={OC}&target=prec&type=XML&ID={판례일련번호}`
- 인증키(`OC`)는 GitHub Secrets의 `LAW_OC` 에서 읽는다

**백필(과거 전량 1회 수집)이 본체다.** 검색어 40개 × 알짜 약 10건 = 약 400건 = 2년치.
하루 200회 상한이므로 **3일에 나눠 실행**한다.
