# data/scripts/ — 완성 대본

회차별 대본을 `{회차}.json` 으로 저장한다. `script.yml` 이 만들고 갱신한다.

**저장 전 반드시 `python3 src/validate_script.py <파일>` 을 통과해야 한다.**
오류가 하나라도 있으면 저장하지 않고 재생성한다.

## 검증 중에 잡은 실제 결함 3건

교차 검증의 목적은 대본을 얻는 게 아니라 **프롬프트의 결함을 찾는 것**이다. 세 건이 나왔다.

### 1. 생성 프롬프트와 평가 프롬프트가 서로 어긋나 있었다

- **증상**: 평가 B항은 "50초 안에 걸린 것을 제시하라"고 요구하는데, 생성 프롬프트의 5단 구조는
  금액을 언제 꺼낼지 말하지 않았다. 그 결과 대본에서 **금액이 323초에야** 나왔다
- **원인**: 도입 훅의 "결말·금액 노출 금지"와 B항의 "걸린 것 제시"가 충돌하는 것처럼 읽혔다
- **수정**: 구간을 갈랐다. **0~22초 금액 금지 / 22~50초 다투는 재산의 크기 제시 / 4막 판결 금액 특정**
- `validate_script.py` 에 기계 검사 추가

### 2. 총점만 보면 한 항목이 무너진 대본이 통과한다

- **증상**: 총점 87점인데 B항이 15/20(75%)이었다. 다른 항목에서 벌어 가린 것이다
- **수정**: `verdict` 가 `pass` 이려면 **모든 항목이 배점의 60% 이상**이라는 조건을 추가

### 3. 잘라내기 표시가 파일 안에 두 번 있었다

- **증상**: `script_gen.md` 안에 `PROMPT:BEGIN` 주석이 사용법 설명과 실제 마커로 두 번 등장
- **영향**: 워크플로가 프롬프트를 잘못 잘라내 엉뚱한 텍스트를 모델에게 보낼 수 있었다
- **수정**: 설명 쪽에서 주석 형태를 뺐다. 4개 파일 모두 마커가 정확히 한 쌍인지 확인 완료

> 하급심의 `참조조문` 공백 문제는 별도 건이다. `../cases/README.md` 참조.

## 대본 형식

`script_gen.md` 의 "출력 형식" 항목이 기준이다. 핵심만 적으면:

```
meta            제목 후보·줄거리·컷 수
anonymization   익명화 기록 (극중명·금액 배율·판사 실명 삭제 확인)
law             인용 조문과 그 출처 경로
characters      등장인물 ↔ 고정 배우 7명 매핑
acts[]          6개 막 (hook + 1~5막)
  cuts[]        컷 하나 = 화면 하나. 배경·인물·포즈·대사·자막·소리·그래픽
shorts[]        쇼츠 3편의 구간 지정
youtube         제목·설명·챕터·고정 댓글
```
