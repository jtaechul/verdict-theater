# state/ — 파이프라인의 두뇌

이 폴더의 파일들이 **"어느 회차가 지금 어디까지 진행됐는지"** 를 기억한다.
이게 없으면 자동 실행이 다시 돌 때 같은 회차를 두 번 만들거나, 만들다 만 회차를 빠뜨린다.

**모든 워크플로는 시작할 때 이 파일들을 읽고, 끝날 때 갱신한다.** (지침서 3번)

지금은 아직 아무것도 안 만들었으므로 **전부 비어 있는 것이 정상**이다.
`{}` 는 "빈 목록", `[]` 도 "빈 목록"이라는 뜻이다.

---

## episodes.json — 회차 상태 (핵심)

회차 번호(`EP001`, `EP002`, …)를 열쇠로 삼아, 회차 하나당 기록 하나를 담는다.

**현재 내용**: `{}` — 아직 회차 없음

**회차가 하나 생기면 이런 모양이 된다** (지침서 3번 형식 그대로)

```json
{
  "EP001": {
    "case_id": "622261",
    "gate_score": 78,
    "stage": "published",
    "script_score": 86,
    "revise_count": 1,
    "case_type": "유류분",
    "longform_id": "유튜브영상ID",
    "shorts": ["ID1", "ID2", "ID3"],
    "published_at": "2026-08-05",
    "shorts_published": ["2026-08-06", "2026-08-07", "2026-08-09"]
  }
}
```

| 항목 | 뜻 |
|---|---|
| `case_id` | 법제처 판례일련번호. `data/cases/{번호}.json` 파일과 짝이 된다 |
| `gate_score` | 판례 드라마성 점수 (100점). 60점 미만은 애초에 여기 못 들어온다 |
| `stage` | 지금 어디까지 왔는지. 아래 표 참조 |
| `script_score` | 대본 평가 점수 (100점). 목표 80점 |
| `revise_count` | 대본을 몇 번 고쳤는지. **최대 3회** |
| `case_type` | 사건 유형(유류분·명의신탁 등). 같은 유형 **연속 2편 초과 금지** 판정에 쓴다 |
| `longform_id` | 12분 본편의 유튜브 영상 ID |
| `shorts` | 쇼츠 3편의 유튜브 영상 ID |
| `published_at` | 본편 공개일 |
| `shorts_published` | 쇼츠 3편 각각의 공개일 (+1일 / +2일 / +4일) |

### stage 값 — 진행 단계

```
selected → scripting → evaluated → rendering
  → uploaded_private → approved → published
```

| 값 | 뜻 |
|---|---|
| `selected` | 판례가 선정됨. 대본 없음 |
| `scripting` | 대본 만드는 중 |
| `evaluated` | 대본 평가·개선까지 끝남 |
| `rendering` | 영상 만드는 중 |
| `uploaded_private` | 유튜브에 **비공개**로 올라감 → 손님이 확인할 차례 |
| `approved` | 손님이 승인함 |
| `published` | 공개됨. 완료 |

**각 워크플로는 자기가 처리할 단계의 회차만 집어간다.**
중간에 실패하면 그 단계에 그대로 남아 있어서, 다음 실행 때 저절로 다시 시도된다.

## queue.json — 대기열

게이트(선정 심사)를 통과한 판례 후보를 **점수 높은 순으로** 줄 세운 목록.
물량이 여유로우면 위에서부터 쓰고, 부족하면 자연히 낮은 점수까지 내려간다.

**현재 내용**: `[]` — 아직 후보 없음

**후보가 쌓이면 이런 모양이 된다**

```json
[
  { "case_id": "622261", "gate_score": 78, "case_type": "유류분", "사건명": "유류분반환청구", "선고일자": "2024-05-29" }
]
```

## calendar.json — 발행 일정

언제 무엇을 올릴지 적어두는 달력. 롱폼 주 4편 + 쇼츠 주 12편.

**현재 내용**: `[]` — 아직 일정 없음

**일정이 잡히면 이런 모양이 된다**

```json
[
  { "date": "2026-08-05", "time": "19:20", "episode": "EP001", "type": "longform" },
  { "date": "2026-08-06", "time": "20:10", "episode": "EP001", "type": "short", "index": 1 }
]
```

- 롱폼 발행일 기준 **+1일 / +2일 / +4일** 에 쇼츠 1·2·3번
- **같은 날 3편 동시 업로드 절대 금지** (조각내기 신호가 된다)
- 시간대는 매번 조금씩 다르게 (완전히 규칙적이면 양산 신호가 된다)

## rejected.json — 개선 실패 기록 (학습용)

대본을 3번 고쳐도 80점을 못 넘긴 회차의 특징을 적어둔다.
**폐기하지 않는다.** 최고 점수 버전으로 발행하되, 왜 안 됐는지만 남긴다.

이 기록이 쌓이면 **"이런 유형의 판례는 애초에 뽑지 말자"** 는 판단 근거가 되어,
게이트 점수 기준을 스스로 보정하게 된다. (지침서 4-2번)

**현재 내용**: `[]` — 아직 실패 기록 없음

**기록이 쌓이면 이런 모양이 된다**

```json
[
  {
    "episode": "EP007",
    "case_id": "631204",
    "case_type": "명의신탁",
    "gate_score": 63,
    "best_script_score": 71,
    "weak_items": ["A. 3초 관문", "C. 중반 유지"],
    "note": "반전이 없고 당사자 서술이 짧아 창작 기반이 부족했음"
  }
]
```

---

## 주의

- 이 파일들은 **자동 실행이 직접 고쳐 쓴다.** 손으로 편집하실 일은 없다.
- 형식이 깨지면(쉼표 하나 빠져도) 워크플로 전체가 멈춘다.
